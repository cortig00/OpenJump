# Native media probe pilot contract

This is a bounded implementation/test seam for indexing presentation timestamps and decoding exact indexed frames from a locally owned clip. It is not a complete A003 implementation, production media importer, accuracy claim, camera/photo/file integration, encoder feature, or clinical/hardware validation.

`MediaProbe` retains each source `CMTime` and exposes canonical microseconds using scale 1,000,000 and `.roundHalfAwayFromZero`. Only valid numeric positive-timescale, nonnegative epoch-zero times are accepted. Semantic time equality uses `CMTimeCompare`; duplicate source timestamps and distinct source times collapsing to one canonical microsecond are rejected. Frames are sorted by presentation time while retaining source times. Frame ordinal is only the index identity, not evidence of decoded pixels. Image requests must equal an indexed source time exactly, and image-generator actual time must semantically equal that request; no nearest-frame fallback is permitted. A manifest is bound to the normalized source URL used to inspect it; this pilot does not guarantee identity against later mutation of a file at that path.

The pilot accepts only one 320x240 video track, no audio, and identity preferred transform. It bounds the index at 256 samples, reads compressed sample timing on the source axis, and fails closed on unsupported layouts, invalid timestamps, reader failures, or image decode/time mismatch. Writer readiness, writer completion, and each image-generator request have finite 10-second operation deadlines with cancellation. It does not shift timestamps, infer frame rate, support B-frame behavior as a qualified contract, or claim arbitrary-asset support. The writer fixtures use a 600-timescale source axis and an explicit tail after the last frame; fixtures begin at epoch zero. The pilot normalizer's handling of nonzero PTS is not end-to-end qualified.

XCTest creates ephemeral H.264 MOV files (six frames, no audio) with fixed broad binary frame-ID cells (three bits encode six frame identities). The independent test oracle examines decoded bitmap cells; hand-authored timestamp expectations are separate from production normalization. CFR and VFR tests compare every indexed source PTS against independent cadence ticks using semantic `CMTimeCompare`, and log actual rational source PTS and decoded pixel IDs. Fixture directories are unique temporary directories removed by `defer`; no media binary is checked in. Codec/HDR input enforcement is not qualified; H.264 all-keyframe is the only fixture format this suite is designed to exercise. Media runtime execution remains unverified as detailed below.

## Bounded simulator-readiness diagnostic recipe

The next diagnostic-only source change preserves compile-before-discovery/boot, the 120-second boot command, 240-second readiness command, 420-second build/test commands and 25-minute job budget. Only when the original boot/readiness step concludes **failure**, `apple/ci/diagnose_simulator.py` attempts read-only evidence collection under `$RUNNER_TEMP/apple-simulator-diagnostics`. Cancellation is deliberately not a collection trigger. It never retries boot/readiness, starts or resets services, selects a fallback device/runtime, or changes media code, assertions or compiler settings. The original gate remains failed; runtime tests and screenshot export remain skipped.

The helper requires the discovered explicit UUID and records selected device/runtime, consumer Xcode, UTC start/finish and each probe's command, deadline, exit and timeout. Five read-only probes inspect selected-device fields from `simctl list devices`, the matching runtime from `list runtimes`, selected-device pairing state from `list pairs`, `xcodebuild -version`, and only state/PID/run-count/last-exit fields from `launchctl print` for the runner user's CoreSimulator service. The latter label/domain may be unavailable: nonzero, timeout, unsupported/malformed or clipped responses are **unknown**, never health PASS. No raw service output, logs, environment, process arguments, screenshots, media or xcresult are saved. Captures are memory-capped at 64 KiB per command; only allowlisted, sanitized fields enter the small JSON/text reports. Probe deadlines are at most seven seconds, with a 40-second total collection budget (below 45 seconds); command timeout kills only that probe's direct child.

An `always()` boot-failure guard runs collection and uploads only `report.json`/`report.txt`, using the existing pinned artifact action and three-day retention. The always-run gate summary keeps the original boot failure explicit and labels diagnostic collection as evidence, not a health verdict. Diagnostic collection/upload is best-effort and cannot convert the boot failure to success. The prototype screenshot artifact remains separately gated on successful real XCTest execution; a SpringBoard image is not substituted.

Local stdlib regression tests exercise bounded direct-child timeout/nonzero behavior, required UUID input, selected-field sanitization, output limits, unknown responses, budget exhaustion and the absence of repeated boot commands. These helper tests and the real diagnostic collection below are not Swift/media runtime proof. Full A003/G0, hardware/clinical/physical-clock, retiming, codec/HDR, iPad, import/camera and encoder qualification remain out of scope. No paid service, version change, timeout increase or runtime fallback is introduced.
